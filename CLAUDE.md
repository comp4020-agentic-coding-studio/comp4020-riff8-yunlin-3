# Your harness

Colophon is a shared, anonymous, permanent handscroll of colophons, after
the Chinese handscroll tradition. Visitors leave one-line notes (max 320 characters) that cannot be
edited or deleted, signed with a seal they choose by meaning from a curated
English/Chinese dictionary and written in an ink from a fixed palette.
Confirmed notes appear on every open session within about a second. The
notes are the scroll: a silk-mounted handscroll read right to left, newest
at the left end and first in the page, one sheet per line sized by its
length, a frontispiece (引首) at the oldest end, a fixed writing dock, an
overview strip, ink-in typing, a lantern launch and a fan opening. Small, quiet,
finished; not a platform.

## Stack and layout

Plain `node:http` server run directly from `.ts` (Node 24 strips types),
`node:sqlite`, no framework, one runtime dependency (`marked`, for `/readme/`).

- `src/server.ts` --- routes (`/`, `/colophons`, `/events`, `/seal`,
  `/readme/`, `/adr/<slug>/`), request-body cap, static files, the one
  error boundary around every request
- `src/db.ts` --- opens the SQLite file (`/data` on Fly), colophon and seal
  claim queries
- `src/migrate.ts` --- idempotent schema migration, run on every boot
- `src/live.ts` --- server-sent events: stream cap, keepalive, broadcast,
  `Last-Event-ID` replay
- `src/render.ts` --- every HTML page as template strings
- `src/dictionary.ts` --- the only import for the seal dictionary: themes,
  lookup and ranked English search; rows live in `src/dictionary/<theme>.ts`
- `src/seal.ts` --- hash-glyph fallback and which seal an entry or visitor has
- `src/ink.ts` --- the fixed ink palette
- `src/html.ts` --- `escapeHtml`
- `src/cookies.ts` --- the anonymous `seal` token cookie
- `src/markdown.ts` --- README and ADR to HTML
- `src/log.ts` --- logfmt action lines and the `who=<glyph>#<tag>` pseudonym
  (`docs/adr/0002-who-did-what.md`)
- `public/app.js` --- progressive enhancement: live append, ink-in typing,
  background submit, the lantern, the dock's measured height and
  screen-reader announcements; user text only via `textContent`
- `public/scroll.js` --- the handscroll's motion on a native scroller: eased
  wheel and keys, arrivals that keep a reader in place, resize that keeps
  the sheet in view, the overview strip; geometry is measured on layout
  changes only, and each scroll frame is arithmetic
- `public/fan.js` --- loaded in `<head>`; plays the fan once per session
- `public/styles.css` --- the theme: mount, cloth, inks, dock, lantern, fan
- `public/scroll.css` --- the handscroll: right-to-left sheets, rollers,
  overview strip
- `public/painting.svg` --- the watercolour, generated by `scripts/paint.py`
  (rerun it rather than hand-editing); only the header wash now
- `public/scroll.avif` --- the Wang Yi handscroll photograph
- `public/favicon.svg`
- `docs/adr/` --- decision records, served under `/adr/`
- `scripts/seed.ts` --- fills a scratch database (needs an explicit
  `DB_PATH`) for local testing

## Design tokens

- `--paper` `#f3ede1` the sheet everything is written on
- `--ink` / `--ink-soft` body text and secondary text
- `--seal` `#a8402c` means only "this colophon is yours"; nothing else is
  red. Its marks: your own lines, and their ticks on the overview strip
- ink palette (`src/ink.ts`, classes `ink--<key>`): `mo-lan` `#2a4f9a`
  default, `dian-qing` `#1f3a6e`, `shi-lu` `#2f6b57`, `zi` `#6a3a5c`, `mo`
  `#2b2721`; only ever a visitor's own text
- `--paper-shade` `#ebe3d3` the darkest any texture behind text gets;
  `--lantern-paper` `#f6e6c4` the lantern body; every ink meets 4.5:1 on
  both (`spec/ink-palette.test.ts`)
- `--sheet-short` / `--sheet-mid` / `--sheet-long` fixed sheet widths by
  line length (`scroll.css`); fixed lengths, so every sheet's box is known
  before it renders
- `--dock-h` the dock's collapsed height, set per breakpoint in CSS and
  refined by `app.js`; `--dock-room` the dock's real, possibly expanded
  height, set by `app.js`. The page's bottom padding and `scroll-padding`
  use `--dock-room`, falling back to `--dock-h` with no script
- scenery, from the painting, never a visitor's text and never "yours":
  `--spruce`, `--moss`, `--granite`, `--clay`, `--sky`, mount silk `--silk`
  / `--silk-dark`, `--gilt` edge, roller woods `--wood*`

## Working agreement

- Commit small and often, one idea per commit. Run `pnpm check` (with the app
  running) first and commit only when it exits 0 --- gate on the command's own
  exit code, never on a pipe into `grep` or a `;` chain. The server reads
  `README.md` and `docs/adr/` once at startup: restart it after editing
  them, or the README check fails against stale text. Push `main` after each green commit
  (in a pod run the harness pushes when the run stops instead). Never commit
  or push on red; fix or revert first. Never commit secrets.
- After any UI or layout change, open the running app in a real browser
  (`agent-browser`), screenshot at 1920x1080 and 390x844, and read the
  screenshots: no horizontal scroll, controls reachable and tappable, art not
  clipped, text legible over the cloth, animations finishing and leaving
  nothing behind. Never claim a visual check you didn't do.
- Every animation respects `prefers-reduced-motion`; decorative art and
  lanterns are `aria-hidden`; every control has a keyboard path and a visible
  focus state; text keeps 4.5:1 contrast on every surface it sits on.
- The SQLite file lives on persistent storage. Migrations are idempotent and
  tested against a database that already has rows. Never drop or rewrite
  existing colophons.
- `TODO.md` is the running to-do list (Now, Next, Done, Context); update it
  in the same commit as the work it records.
- A claim in `README.md`, `CLAUDE.md`, the ADRs in `docs/adr/` and `spec/`
  must hold in all of them; change them together, in the same commit.

## Rules

Rules for working on Colophon, derived from what `README.md` argues good means
here. If a change would break one of these, the argument in `README.md` is
what has to change first, in the same commit.

- Never add an account, profile, avatar, name field, like, reply, thread,
  notification, presence or typing indicator. A visitor is their seal and
  nothing else: an anonymous per-browser token, signing with its hash glyph
  or one seal chosen from `src/dictionary.ts`. Never accept free-text seals
  or transliterate input; that's a name field in disguise.
- A seal claim is decided by the `seal_claims` UNIQUE constraints, never a
  check-then-insert; each colophon snapshots its seal and ink, and changing
  seals never rewrites an old row (`docs/adr/0001-seal-claims.md`).
- Only a confirmed colophon is broadcast, from the same code path that
  inserts it, after the insert. Drafts never leave the visitor's page.
- The lantern launches only on a 2xx from `POST /colophons`; the typed text
  stays put until then. Nothing about the core flow may depend on it.
- Inks are posted as palette keys and rendered as `ink--<key>` classes.
  Never accept a colour value and never put visitor input in a `style`
  attribute.
- Never add a way to edit or delete a colophon after it's written, and never
  auto-truncate one that's too long — reject it at the boundary and ask the
  visitor to shorten it themselves. Silent mutation of what someone wrote is
  worse than a rejected submission.
- Every colophon body is untrusted, persisted, and re-rendered as HTML to
  every future visitor: it must always go through `escapeHtml` before it
  reaches a template string. No new template may interpolate user text
  unescaped.
- The core interaction (reading the scroll, writing a colophon) must keep
  working with JavaScript disabled — a plain HTML form posting to the server.
  Anything that needs a script is a progressive enhancement on top, not a
  replacement.
- Never leave keyboard focus on an element you're about to disable or
  remove; after a submit, focus stays in the textarea.
- Anything fixed over the page leaves room for itself: body padding and
  `scroll-padding` come from `--dock-room` (falling back to `--dock-h`), so
  the dock never covers focused content.
- A keyboard path through the scroll follows reading order: the list is
  newest first in the DOM, matching the screen. Never reorder it with CSS
  alone.
- Every value from the URL that reaches a page (`theme`, `page`, `error`) is
  validated against a fixed list before use and never echoed.
- Every async request handler sits inside the one error boundary in
  `src/server.ts`; a half-sent body must never take the process down.
- The log names visitors only as `who=<glyph>#<tag>`, through `src/log.ts`:
  never a token, cookie, body or query string. Reading (streams) is logged
  as counts only.
- A new line is announced to screen readers through the one `role=status`
  line; presence never is.
- The textarea has no `maxlength`: the browser would silently cut a paste
  mid-word. The server is the only length boundary; the counter shows how
  far over.
- Pages that show per-visitor state (`/`, `/seal`) are never cached, and
  reload when restored from the back-forward cache.
- Never hide off-screen sheets with `content-visibility: hidden`:
  find-in-page and copy must reach every line.
- If the accent colour (`--seal`) gets a second meaning beyond "this colophon
  is yours," that's a sign the design has drifted, not a sign to add a second
  colour.
- When a check finds a real bug, the fix is a new `spec/` test or a rule in
  this file, not just a patched line with no trace of what went wrong. When
  you are corrected, put the rule here.
